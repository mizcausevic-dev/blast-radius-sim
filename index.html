How it works

The catalog is a directed graph. Failures propagate to a fixed point. A service is down if any hard dependency is down, and degraded if a soft dependency is impaired or a hard dependency is degraded. Statuses only ever get worse, so propagation terminates even when the graph has cycles. Cycles are found with Tarjan's strongly connected components algorithm. Composite availability multiplies a service's own availability by that of each hard dependency, assuming failures are independent. Services inside a cycle are left out, because their availability isn't well-defined.

The sample catalog is fictional. It has planted smells (checkout hard-depending on a tier-2 fraud service, a catalog/inventory cycle, and shared data stores every entrypoint needs) so the analyzer has something to find. Everything runs locally in your browser.
